## 1. 目标、范围与完成定义

### 1.1 产品目标

在现有 Go 后端上完成一个支持用户、知识内容、关注推荐、安全交流和协作创作的社区后端。所有功能以真实数据、可验证权限、可恢复的数据和可重复的测试作为交付标准。

### 1.2 全部功能范围

1. 邮箱认证、账号资料、安全设置、会话撤销和隐私/账号注销。
2. 话题、问题、回答、文章、专栏、系列、草稿、版本及协作审阅。
3. 点赞/反对、评论、关注、收藏、历史、通知、搜索和媒体。
4. 最新、关注、热门、推荐 Feed，兴趣、屏蔽、负反馈和创作者统计。
5. 私信设置、会话请求、消息、已读、举报和隐私控制。
6. 专栏成员、邀请、所有权、系列目录、版本冲突、审阅及发布。
7. 敏感词、审核、举报、申诉、权限、审计和安全运营。
8. MySQL 数据与迁移、Redis、可靠异步任务、监控、测试与部署。

不纳入：支付、视频、群聊、实时多人协同编辑、机器学习模型、商业化和端到端加密私信。外部搜索和云存储为可插拔增强，不能以接口空实现宣称生产可用。

### 1.3 定义完成

每个模块必须满足：契约明确；实现和权限经过真实集成测试；故障和重试有定义；API 文档、迁移和配置与代码一致；残留问题明确登记。只有第 17 节门禁全部通过并提供证据才可称后端完成。部署到真实环境另需用户授权与真实配置，不以模拟测试宣称已经上线。

## 3. 架构与公共约定

### 3.1 架构

沿用现有 `Gin routes → controller → logic → dao/mysql|redis`；controller 负责认证上下文、绑定、响应；logic 负责授权、状态和事务边界；DAO 负责参数化查询。避免所有模块绑定全局连接：新增逻辑优先设计可注入的事务、时钟、邮件/存储接口以支持集成测试。

MySQL 是账号、内容、关系、通知、私信和审计的事实来源。Redis 存验证码、限流与缓存，可丢失但需有明确降级。搜索索引和指标为可重建派生数据。`request_id` 贯穿日志、任务与审计；禁止记录密码、验证码、token、私信正文、完整邮箱或加密密钥。

### 3.2 ID、时间、分页

- 对外所有雪花业务 ID 为十进制字符串；数据库使用与现有字段一致的 BIGINT，严格验证正数范围。
- 业务时间以 UTC 持久化/比较，JSON 输出 RFC3339；统一确认 MySQL 连接时区及精度，测试跨日和同时刻排序。
- 列表默认 limit 20、最大 50；无更多返回空 next cursor。游标必须有版本、列表类型、过滤条件、排序键，私人列表绑定用户；不可信游标严格验证，必要时签名，不能将 base64 当加密或权限校验。
- 时间流使用稳定的 `(time, type, id)` keyset 排序及匹配谓词；推荐快照绑定用户和版本，有 TTL，过期返回明确业务码。二次检查当前可见性，防缓存泄露。

### 3.3 HTTP/API 兼容

现有 API 前缀 `/api/v1`、响应 `{code,msg,data}`、业务错误通常 HTTP 200。现有客户端依赖业务码，**不得单方面改成 HTTP 401**。非业务层异常和网关错误按真实 HTTP 处理。新业务码使用显式数值并追加，保留已发布数字和结构；参数、字段、鉴权和分页变更需双版本/兼容期。

旧 `/signup`、`/login`、`/post`、`/posts2/`、`/vote` 等列入兼容清单：先核查使用者，补认证及可见性；若无法安全兼容，通过版本化弃用计划替代，禁止悄悄移除或留安全绕过。

### 3.4 通用一致性

- 每个状态变更采用 DB 事务、唯一索引与条件更新；读取后更新必须防止并发覆盖。明确锁顺序，处理死锁重试。
- 关系和计数的权威语义明确，重复请求幂等，禁止负数；消息、邮件、索引、通知等外部副作用使用事务性 outbox 或同库事务。
- Outbox 最少一次投递；事件拥有唯一键，消费者幂等。多 worker 使用安全 claim/lease 和超时恢复，失败指数退避、上限、死信、重放与告警；不可承诺跨系统严格 exactly-once。
- 任何缓存命中都不能跳过当前授权、禁用、删除和审核检查。外部依赖故障区分“无数据”和“服务暂不可用”。

## 4. 角色与权限

| 资源/动作 | 游客 | 登录用户 | 作者/所有者 | 编辑 | 审阅者 | 审核员/管理员 |
| --- | --- | --- | --- | --- | --- | --- |
| 公开、通过审核内容 | 读 | 读/互动 | 读/维护自己的 | 依成员权限 | 依成员权限 | 依法规和授权治理 |
| 草稿、私有版本、审阅评论 | 否 | 否 | 是 | 是 | 可读/评论 | 默认不可读；举报授权的证据例外 |
| 专栏成员与角色 | 否 | 受限 | 邀请/移除/转移 | 只读必要信息 | 只读必要信息 | 治理不等于任意读取私信 |
| 私信 | 否 | 仅本人参与会话 | 同左 | 同左 | 同左 | 仅授权举报证据且审计 |

权限来源为当前数据库状态，不信任客户端 ID、角色或旧 token。私有对象不存在与无权使用统一不可枚举响应。屏蔽、账号禁用和内容审核决定的优先级高于推荐、缓存和关注关系。高风险操作的身份再验证及账号注销/保留期以负责人确认后的策略为准。

## 5. 域 A：认证、账号和隐私

### A1 邮箱注册与登录

- 复用现有 `/auth/send-code`、`/auth/register`、`/auth/login`、`/auth/me`。统一邮箱规范化、唯一索引、用户名、UTF-8 长度和 bcrypt 字节上限，注册并发冲突以数据库为最终依据。
- 验证码加密安全随机、目的隔离、TTL、失败次数、邮箱/IP 限流，比较与消费原子执行。Redis 故障不得变成错误验证码或绕过限流。发送与认证对外避免账号枚举；超时、发信失败不记录敏感信息。
- JWT 显式限定算法、过期、签名、用户禁用状态与版本；`logout-all`、重置和禁用应使旧 token 失效。密码重置采用一次性 token 摘要，消费、更新密码、递增 token 版本同事务。
- 旧账号无真实邮箱时保留兼容绑定流程；占位邮箱不能当真实验证邮箱。

### A2 个人资料和注销

- 当前用户可修改本人公开资料；公开用户 API 不返回邮箱。头像资源引用需验证所属和可用状态。
- 明确注销是软删除、去标识化还是硬删除；在政策确定之前默认停用账号、撤销凭据、隔离后台清理，绝不声称全部备份立即删除。逐表列出 user、私信、事件、报告证据、审计、通知、媒体处理规则，给出保留与法定保全例外；重试幂等并记录非敏感审计。
- 验收：多线程同验证码只成功一次；禁用/重置后旧 JWT 失效；枚举、越权、迁移和清理策略经过集成测试。

## 6. 域 B：内容、草稿、媒体与搜索

### B1 内容生命周期

统一用户、问题、回答、文章、专栏、系列、评论的公开可见性：对象、父级、作者/专栏状态、审核状态、软删除、读者屏蔽均满足要求才可公开。设计公共 `visibility` 判定入口及 SQL 查询构造，同时禁止把业务状态简化成只检查一个字段。

状态变更（草稿→待审→公开→隔离/下架/删除）使用条件更新与审计。审核词表/依赖不可用时 fail-closed，保留用户输入并返回重试；安全审核通过与协作审阅通过是两个独立条件。重复发布、下架和事务故障有明确语义。

### B2 草稿与版本

- 编辑必须校验作者/专栏角色，`base_version` CAS；冲突返回当前版本标识，不泄露他人草稿。不可变版本绑定内容摘要、操作者、时间。
- 恢复历史版本创建新草稿并重新审核，不直接修改已公开版本。审阅通过绑定 revision；任何新修改使旧批准失效。
- Markdown 和预览统一使用服务端白名单，禁用原始 HTML、脚本及危险 URL；安全规则更新需回归已有内容。

### B3 媒体

校验上传者、资源归属、实际魔数、允许 MIME、解码后尺寸/像素、文件大小，剥离或明确定义 EXIF；禁止危险 SVG 和路径穿越。随机服务端 key，上传临时文件原子落地；数据库记录状态，失败清理可重试。公开/私有资源访问必须匹配内容与用户权限。

在真实 Compose 容器中验证应用配置路径是否正是 `/app/uploads`，重建后仍可读取；备份同时覆盖数据库和对象，制定一致性恢复。S3/MinIO 若纳入发布，必须提供真实适配、隔离集成测试和最小权限配置，不能把本地实现称为对象存储已完成。

### B4 搜索

现有 MySQL 搜索应覆盖经授权的问题、回答、文章、用户、话题、专栏；分页排序稳定，输入参数化，防止被删除/隐藏/屏蔽内容泄露。外部索引若启用，MySQL 是权威来源：按对象版本幂等 upsert/delete，返回时复核可见性，支持重建、追赶和回滚；搜索不可用有明确可重试或经过测试的 MySQL 降级。

验收：草稿/禁用作者/隐私对象不能从列表、搜索、Feed、媒体等旁路访问；审核故障不会公开；上传重建恢复成功。

## 7. 域 C：互动、话题、收藏、通知

- 用户/话题/专栏关注、问题关注、回答投票、文章互动、收藏夹/历史和评论：联合唯一键及事务保证幂等；投票从 -1 到 1 的计数变化为 +2；自关注拒绝；删除对象和屏蔽策略统一。
- 通知只在事实状态真实变化时产生，不能因为重试重复；明确“取消后再次操作”的新通知语义。通知与业务事务同库写入或 outbox，任务失败不丢。
- 分页、单条/全部已读、未读数均按接收者过滤；被删目标返回安全占位。通知偏好、屏蔽联动和安全必要通知有固定规则；通知聚合不改变底层事实。
- 审计和评论内容不可被用户构造 SQL/HTML 执行；每个接口验证对象存在和权限。对统计缓存做事实表对账/重建工具，工具默认只读，修复需显式参数和备份。

验收：并发重复操作只有一个事实关系，计数与重算一致；越权、重复通知、删除目标均覆盖。

## 8. 域 D：关注 Feed、推荐、反馈与统计

### D1 关注流

复用 `/feed/following`，内容候选来自关注作者、话题和专栏，按 `(类型,ID)` 去重并合并 sources；只返回用户有权查看的问答和文章。稳定排序基于真实公开时间 + 类型 + ID；固定数据集各页无重漏。不同来源命中、共同时间戳、删除、屏蔽、取消关注及无关系都有确定结果。

查询至少 `limit+1` 个有效项；如果过滤发生在 SQL 后，继续扫描至凑足页面、候选耗尽或达到明确安全上限，避免把有后续数据错误报告为 `has_more=false`。索引由真实 `EXPLAIN` 与测试负载决定。

### D2 推荐

推荐既有实现要先验证：候选、热度、兴趣、关注、反馈、屏蔽、关闭个性化和快照有效期；扩展而非并行重写。第一版确定性可解释规则；返回可枚举推荐理由与版本；冷启动基于公开热门和新鲜内容。单作者/话题过度集中设可配置上限。

快照每页复核当前权限；更改屏蔽或可见性立即生效；过期返回 `CodeFeedExpired` 或兼容错误，提示刷新。关闭行为个性化后不得使用浏览/点击历史，关注流仍可按主动关注展示。

### D3 事件和统计

`/events` 的客户端事件是分析信号，不可当关注/投票等事实。明确服务端签发 exposure ID、会话/用户绑定、过期与点击关联；无有效曝光的点击不进入 CTR 分子。有效曝光为卡片 ≥50% 可见且持续 ≥1 秒。有效阅读口径以增长 PRD 为基准，个人/内容/UTC 日去重；过滤作者自身和明显无效流量，不能声称无法验证的精准人数。

事件批量大小、字段类型、时间窗口与限流明确。匿名标识短期存活且不使用明文 IP；遵守开关、保留与删除策略。日聚合以唯一维度和确定性版本幂等重算，定义最新版本查询、水位、迟到事件、回填、失败和 24 小时数据延迟；不得叠加历史版本导致翻倍。创作者只访问自己的聚合数据，返回 `as_of`、时区和口径版本，缺失不伪造零。

验收：B05 并发 CAS；多来源去重；曝光重试/伪造/乱序；用户关闭个性化；老快照下架；统计重跑与迟到数据。

## 9. 域 E：私信与安全沟通

### E1 状态和权限

默认接收策略为 `following`：接收方关注发起方才能新建请求；可选 `nobody`、`everyone`。一个参与者对最多一个有效会话；pending 只允许发起方的一条首信。仅接收方可接受/拒绝；拒绝或关闭后重新发起默认冷却 7 天；已建立会话的私信设置变更默认不自动关闭，但任一方屏蔽、禁用必须立即阻止发送。不可联系原因统一，防枚举。

消息纯文本 1–2000 Unicode 字符；按 `(conversation_id,sender_id,client_message_id)` 幂等，重试返回原结果。会话创建、首信、成员、outbox 在同事务；pending 限一条须由锁/条件约束保障。发送时在同一隔离语义下检查成员、状态、双向屏蔽；权限查询错误 fail-closed，避免 B01。

### E2 已读、隐藏与举报

每成员维护单调已读标记，必须属于该会话且不超越其可见消息；未读只算对方且可见消息；read-receipt 设置关闭时对方不得获得已读信息。隐藏仅对本人，不能删对方副本。页面有界轮询；数据库持久化后可以断线补拉，不承诺设备已送达。

仅接收者可举报其收到的消息；审核员按最小范围获取授权证据，不能处理自己的对话。加密证据实际必须实现 AES-GCM 的随机 nonce、密钥版本、认证解密、轮换、失败关闭和访问审计；密钥与 DB 分离，不得记录正文。验证 012 表不仅存在、还真正被举报链路使用。

限流按账号/会话/可信 IP 设置并有后端故障策略；默认每账号每小时 20 个新请求、每会话每分钟 30 条，生产可配。保留期及账号删除须先确定，禁止宣称端到端加密。

验收：待处理多首信和立即重发被拒；双向屏蔽/竞态、重复发送、跨会话 ID、成员越权、举报证据与加密轮换测试。

## 10. 域 F：专栏协作、系列、版本和审阅

### F1 成员与邀请

角色 owner、editor、reviewer；作者和成员的访问矩阵以协作 PRD 为准。一个专栏唯一 owner；邀请仅已有用户、7 天有效、接受前不授予角色，撤销/过期/重复与并发幂等。禁止通过邀请枚举用户；移除或禁用成员立即失权。所有权转移先检查目标资格、双向确认、版本/事务锁、唯一 owner 和审计；单人专栏有明确跳过协作审阅路径。

### F2 系列

系列属于专栏；每系列最多 200 文章，一文可在多个系列出现，但每系列不重复，仅引用本专栏拥有权限的文章。目录重排传完整 ID 列表和 base_version，检验成员、集合一致、无重复；原子更新，不允许并发丢失或位置唯一索引碰撞。读者只看当前可见文章，作者可见不可用占位；不能通过目录泄露草稿。

### F3 审阅与发布

绑定不可变 revision：编辑提交→其他成员批准/退回→owner 发布→安全审核。禁止自批，版本变化取消旧批准。单人所有者跳过协作审阅不代表跳过内容安全审核。审阅决定与文章状态、审计、通知必须原子或可恢复，避免 B04。B03 的 baseVersion 要实际校验；恢复为新草稿，不修改公开版本。

对于 B06 设计一个真实可执行的唯一约束或持锁策略，测试同一版本并发提交；不要依赖含时间戳的唯一键保证 pending 唯一。所有权变动、被移出及审核下架后，私有版本、审阅评论、系列列表不得越权返回。

验收：完整 owner→editor→reviewer 流程、撤权即时生效、自批拒绝、恢复/并发冲突及 fail-closed 审核。

## 11. 域 G：审核、举报、申诉、管理与审计

- 统一举报目标类型与对象权限，举报幂等、限速，举报者仅能查询自身状态。审核队列分页、乐观锁、角色/对象校验，禁止审核员处理自己的对象。
- 审核操作、拒绝原因、隔离/恢复、申诉、封禁及敏感词管理写不可变审计；私信证据只能在授权场景读取并记录访问。申诉同一审核决定最多一个待处理，申诉不自动恢复内容。
- 实现敏感词缓存版本、失效、故障关闭；操作后通过 outbox 通知搜索/Feed/缓存，返回时仍复核 DB 可见性。
- 内容统计、用户列表与治理操作的权限应分别控制。删除或去标识化需遵守已批准政策，避免可识别信息经审计、缓存、搜索残留。

验收：敏感词加载故障下不能公开，举报/申诉并发不重复，跨角色/对象越权和日志泄露检查通过。

## 12. 数据库、迁移与部署

### 12.1 迁移

- 在隔离环境同时演练全新空库、旧基线库以及已执行至 012 的库；检查迁移记录、实际 schema、失败恢复和重复运行。严禁修改或重新执行历史迁移来掩盖 drift。
- 为修复新增 `013+`，按实际最大版本递增；MySQL DDL 隐式提交，非原子迁移必须给出检查点、失败检测和前向修复。正式执行先备份并验证恢复。
- 设计唯一索引前检查既有重复数据，提供只读审计、备份、确定性修复策略；不自动删除用户数据。与前端/旧 API 采用 expand → 双读写/回填 → 切换 → 后续收缩。

### 12.2 生产可运行性

- 定义配置的本地/测试/生产区分，启动校验 secrets、迁移版本、发信、存储和可信代理；HTTPS 与管理接口访问限制由实际部署落实。
- 将 MySQL、媒体备份与恢复点协调，Redis 缓存重建；保护密钥并提供轮换。`/health/live` 与 `/health/ready` 分离，探针不泄露内部详情。
- 指标：API 请求/业务错误率及延迟、数据库连接/慢查询、Redis 故障、任务 backlog/重试/死信、邮件、上传、搜索及审核故障。报警阈值基于测量与运行资源确定，不假装已经部署监控。
- 灰度/回滚：上线前快照、兼容迁移、环境验证、监测；不可逆 DDL 用前向修复或恢复方案，明确 RPO/RTO 由负责人确认。不得将开发 Compose 明文配置当生产配置。

## 13. 对外接口清单与兼容策略

实际路径以 `routes/routes.go` 为权威，开始时输出机器可核对路由清单，并把以下领域映射到已有处理器。表中是能力而非已实现保证：

| 域 | 需要覆盖的 API 能力 | 鉴权 |
| --- | --- | --- |
| auth | 发码、注册、登录、重置、me、资料、绑定、logout-all、注销 | 发码/登录公开；me/绑定/注销需登录 |
| content | 问题/回答/文章/专栏增改查、审核与删除、草稿、媒体、安全预览 | 公开读 optional auth；写入依对象授权 |
| social | 用户/话题/专栏关注、投票、评论、收藏夹、历史 | 关系写入登录；私有资源仅本人 |
| discovery | feed、search、兴趣、偏好、反馈、屏蔽、创作者指标、事件 | 公开流可选认证；偏好和私有指标必须本人 |
| messages | 设置、会话发起/接受/拒绝/关闭、消息、已读、举报 | 必须为参与者；举报和证据另做权限 |
| collab | 系列/排序、成员/邀请/转移、版本、审阅意见与决策、发布 | 专栏角色与对象校验 |
| governance | 公开举报、本人状态/申诉、管理审核、敏感词、审计 | 必须登录；管理由服务端角色控制 |
| operations | live/ready、内部指标、运维重试/对账 | 探针最小信息；内部操作强授权 |

统一页结构沿用现有 `models.PageResult`；增量字段向后兼容。Swagger 由当前注解生成并验证示例，与真实 handler 一致。新接口的请求/响应、约束、错误、幂等键、鉴权和示例必须在具体任务 PR 中补齐；不能把上表当作已完成的 OpenAPI。

## 14. 状态、错误与事件契约

| 场景 | 必须语义 |
| --- | --- |
| 验证码/授权依赖故障 | 服务暂不可用，拒绝敏感操作；不可伪装成成功或无数据 |
| 提交相同操作 | 明确幂等键或自然唯一约束，重复返回相同结果，无额外通知/计数 |
| 版本冲突 | 条件更新受影响行为 0 时返回稳定冲突码；不静默覆盖 |
| 内容不可见 | 对普通访问统一不可见；缓存、搜索、推荐和媒体一致 |
| 推荐快照过期 | 稳定的 `CodeFeedExpired` 或兼容码；前端刷新 |
| 消息请求不允许 | 对外统一不可联系；内部可观察不含敏感正文的分类指标 |
| 外部任务失败 | 保持可见 pending/dead 状态、可重试及可审计；不 silently drop |

事件最低字段：唯一 event_id、类型与版本、aggregate_id、发生时间、request_id、非敏感 payload；消费者验证 schema，并按 event_id 幂等。事件的用户信息最小化，普通 outbox 禁止包含私信正文。

## 15. API 与业务验收场景

1. 注册→登录→提问→回答→点赞/评论→通知：正确权限、去重、计数、审核。
2. 文章→审核→专栏→系列：发布与目录可见；下架后 Feed、搜索、历史、收藏和媒体均遵守权限。
3. 关注作者、话题、专栏命中同一内容：关注流只一条并合并来源；取消关注和屏蔽实时生效。
4. 用户关闭个性化→反馈→撤销→分页：推荐信号和快照按政策变化，不泄露已下架内容。
5. 私信请求→接受→对话→已读→举报→屏蔽：状态正确，无权限用户读不到消息；重试和竞态不丢不重。
6. owner 邀请 editor→修改草稿→reviewer 审阅→owner 发布→恢复历史：严格权限、版本绑定、审核和可恢复性。
7. 举报→管理员隔离→搜索/Feed/详情隐藏→申诉→处理：审计完整、仅授权角色可见。
8. 删除/禁用账号后复测 JWT、公开内容、私信、推荐和事件；执行已确认的保留/清理策略。

## 17. 质量门禁与测试

### 17.1 最低自动化矩阵

- 单元：状态机、策略、错误码稳定、cursor 边界、可见性、推荐规则、敏感信息脱敏、时区和去重。
- MySQL 集成：完整迁移、并发 CAS、唯一约束、事务中途失败、计数对账、首信/冷却、审阅冲突和 owner 唯一；必须运行真实 MySQL，不把跳过当通过。
- Redis 集成：验证码原子消费、限流故障、锁所有权和到期、Feed 快照过期/重建。
- API：三种身份及对象级权限、所有写操作幂等、参数边界、旧接口兼容、输出 envelope 及字符串 ID。
- E2E：第 15 节全部流程，隔离环境使用测试邮箱，不借生产数据；保留失败报告。
- 安全：XSS、SQL 注入、上传魔数/解码炸弹/路径穿越、跨账户 cursor、私信/证据和草稿越权、敏感信息日志。
- 故障/恢复：MySQL、Redis、SMTP、审核、媒体和 worker 中断；备份恢复、任务重放、聚合重算和数据修复。
- 性能：固定种子数据和环境，记录 Feed/搜索/会话分页 QPS、p50/p95/p99、查询计划及资源；目标阈值由负责人基于实际部署确认。

### 17.2 CI

CI 必须覆盖目标分支/PR：`go build ./...`、`go vet ./...`、`go test ./...`，以及真实 MySQL/Redis 集成与浏览器 E2E。明确环境变量及跳过条件，检查测试日志中的 skip；前端构建保留。密码和测试密钥不输出，测试配置不复用真实 `.env`。记录运行结果链接或日志和实际 SHA。

### 17.3 发布门
